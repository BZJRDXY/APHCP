# 项目代码同步规则

**每次修改 APHCP 项目代码，包括脚本、工作流、测试、数据库迁移和可公开的配置模板，都要在该次工作完成必要验证后同步到公开 GitHub 仓库 `BZJRDXY/APHCP` 的 `main`。** 用 `python scripts/sync_github.py --push --message "说明本次改动"` 提交并推送，核对输出的远端提交号，再把该次代码改动视为同步完成。推送失败时如实说明并保留本地修改；恢复后补推。不按键入次数提交，中途草稿在本次改动完成后一起同步。

同步入口从当前工作区提取代码和公开模板，为公开仓库维护独立提交历史。公开协作入口为[审阅指引](../public/review.md)与[验收摘要](../public/status.md)。研究数据、坐标、逐条台账、完整运行回执、私有部署参数、凭据和本地历史不随代码推送。在首次同步或更改文件纳入范围时，用 `python scripts/sync_github.py` 预览文件和树号；可用 `--expect-tree` 固定已核对的内容。GitHub 代码同步与 Pro5000 部署、数据发布分别处理。

每次推送自动从本地已验收回执核对并生成摘要。用 `python scripts/sync_github.py --show-status` 预览；有新验收时更新本地的 `config/public_review_sources.local.json` 指向已核验的回执，再用同一同步命令发布，支持只更新摘要。选择器和回执不公开。验收日期按证据实际日期；只有回执能证明对应同一公开执行代码指纹时才标明该版本已验收。给 GPT 审阅时引用完整 Commit，按该版本查询代码及摘要。
